SAP 社区有一个名为 SAP Development Tech Radar 的项目，用于展示 SAP 技术栈的推荐级别。

页面地址：https://tobiashofmann.github.io/sap-dev-tech-radar/

仓库地址：https://github.com/tobiashofmann/sap-dev-tech-radar

它把 SAP 技术栈中的技术分为 ADOPT / USE / HOLD / STOP 四档，每个象限内再分为 UI / Technology / Tools / Frameworks 四个象限。每个象限内，技术被分为不同的 ring，每个 ring 对应不同的推荐级别。

![SAP Development Tech Radar](https://img.jack-liang.com/01-public/sap_radar.png)

四个 ring 的含义

- **ADOPT** —— 新兴、处于稳定与采用阶段的技术
- **USE** —— 当前推荐使用的稳定技术
- **HOLD** —— 仅在没有替代方案或被绑定到有 EOL 的产品/服务时使用
- **STOP** —— 已过时，存在继任者并有明确 EOL 日期

开发者可以据此判断自己的项目中使用的技术是否符合推荐级别。虽然不是强制的，但是推荐级别是一个很好的参考，可以帮助开发者定位技术方向，避免使用过时的技术。

作为一个日常开发依然基于 GUI 的开发者，我注意到大部分基于 SAP GUI 的技术都被标记为了 STOP，比如 SM30、SE80、SEGW 等。

这意味着这些技术已被SAP弃用，不再推荐使用。

同时我们也能据此知道SAP的的技术演进方向，哪些是SAP主推的，哪些是SAP弃用的。

我看出的几条战略主线

### 主线 1:SAP 在全力推 BTP + Cloud

BTP / Steampunk / Workzone / Cloud ALM / ABAP Cloud / OData v4 全部 ADOPT 或 trend=positive
Neo / XSC / Portal / XSA 全部 STOP 或 deprecated
信号:SAP 不再想让你跑 on-prem,未来要么 BTP 要么 S/4 Cloud

### 主线 2:RAP 是 ABAP 的未来,CDS View Entity 是数据建模的未来

RAP managed / RAP unmanaged / RAP managed draft 三档全 USE/ADOPT
CDS View Entity 在 USE,经典 CDS Views 在 HOLD trend=negative
信号:老 ABAP OO + SEGW + 经典 CDS 的项目,这是给老项目的最直接升级路径

### 主线 3:Eclipse ADT + abapGit + VS Code 是新开发栈

ADT、abapGit、VS Code、BAS、UI5 CLI 全 USE
SAP GUI / SE80 / SEGW 全 STOP
信号:SAP实质上把 GUI 工作流标 deprecated 了——虽然嘴上不说,但 ring 摆在那里

### 主线 4:FPM 复兴 + Web Components 进 ADOPT

FPM 新版(WDA 的现代化继承者)在 ADOPT trend=positive
Web Components 进 ADOPT
信号:SAP 在押注"FPM + 标准 Web Components"作为复杂 UI 的下一代替代品

### 主线 5:Mobile 和 Native SDK 在收缩

Mobile Cards HOLD trend=negative
BTP SDK for Android/iOS HOLD
Fiori for Android/iOS(可能是 deprecated路径)
信号:SAP 押注 MDK(Mobile Development Kit)+响应式 Fiori,Native SDK 退潮
